# Проверка в игре

## Запуск

- Сначала посмотреть, не запущено ли уже: сайт на :3000, игровой сервер на :2567, база на :5432. Обычно `npm run dev` и база работают у разработчика — тогда свой сервер не поднимать, а открыть вкладку: `preview_start` с `url: http://localhost:3000/play`. Не запущено — `preview_start` с `name: fishing-house` (`.claude/launch.json`).
- Разработчик может сидеть в той же комнате-причале: общее (часы, погоду) после проверки вернуть как было.
- Вход: тестовый рыбак. Имя и пароль — в личной памяти Claude (`fishing-house-test-fisher`), в репозитории их нет. Нет записи или база пересоздана — завести нового на `/register` и записать в память. Настоящие данные разработчика не вводить.
- После проверки закрыть вкладку, иначе тестовый герой остаётся стоять в общей комнате.

## Панель скрыта — игру двигать самому

В скрытой панели `requestAnimationFrame` не срабатывает и CSS-переходы стоят. У игры для этого есть `window.FH_GAME` (собирается в конце `app/app/game/engine.ts`):

- `FH_GAME.step(dt)` — один шаг игры. Крутить в цикле с `setTimeout(40)` **в реальном времени**: если прокрутить много шагов разом, сервер сочтёт ходы слишком быстрыми и вернёт героя (`self`).
- `walkTo(x, y)`, `sitDown()`, `standUp()`, `fishAction()`, `bucketAction()`, `packAction()`, `pickUp()`, `putDown()`, `putOn()`, `takeOff()`, `setPack(kind)`.
- `hero`, `bucket`, `pack`, `ghosts`, `fishing`, `room` — состояние, как его видит клиент.
- Время: `setHour(22)` останавливает час только у себя, `setHour(null)` пускает снова; то же делает адрес `/play?hour=22`. `setClock`, `setWeather` — общие часы и погода причала на сервере, меняются у всех.
- Клавиши: `window.dispatchEvent(new KeyboardEvent('keydown', { code: 'KeyQ' }))`.
- Карта целиком и есть кадр, камеры нет: точка карты (x, y) на холсте — (x·k, y·k), где k = `FH_GAME.view.k`.
- DOM после шага обновляется не сразу (Vue) — перед чтением подписи подождать `setTimeout`. Итог CSS-перехода смотреть, временно выставив `transition: none`.

## Окно рюкзака

- Клик и двойной клик — инструментом `computer`: настоящие нажатия доходят и в скрытой панели.
- Удержание и перетаскивание — своими `PointerEvent` на холст; сначала заглушить `canvas.setPointerCapture = () => {}` — на выдуманный pointerId он бросает ошибку.

## Картинка

- Рассмотреть кадр крупно: нарисовать холст игры в отдельный увеличенный `<canvas>` поверх страницы и снять скриншот (`zoom` у скриншота не увеличивает).
- Сравнивать пиксели «до и после» — только при остановленных погоде и времени: подменить `FH_GAME.wx.update` на ясную погоду без ветра и выставить `setHour(12)`. Иначе цвета плывут от оттенка неба, и это выглядит как сдвиг картинки.
- Погоду можно смотреть, не трогая сервер: `const orig = FH_GAME.wx.update; FH_GAME.wx.update = (dt, w) => orig(dt, { kind: 'rain', wind: true })` и прокрутить несколько секунд.
- Виды-картинки (`pets.ts`, `gull.ts`, `crow.ts`, `house.ts`) проверяются и без входа: на любой странице сайта `await import('/_nuxt/game/pets.ts')`, создать вид, вызвать с нужным временем и нарисовать на свой холст поверх `/assets/world.png`.

## Не ошибки правки

- Перезагрузка страницы оставляет старую сессию «призраком» секунд на 20 — сервер ждёт переподключения.
- Игровой сервер разработки (`tsx watch`) перезапускается при любой правке серверного или общего файла (и после `npm run build:world`) и на Windows гибнет без сохранения: герой откатывается к последнему автосохранению (раз в минуту). Герой «не там» — сначала вспомнить про это.
- Правка стиля в `.vue` «не применилась»: dev-сервер Nuxt иногда отдаёт стиль, собранный между двумя правками подряд. Пересохранить файл без изменений и перезагрузить страницу, а не искать ошибку в CSS.
- Координаты из старых заметок и снимков могут быть сняты при другом положении картинки-образца на карте — сверять с `World.pic`.
