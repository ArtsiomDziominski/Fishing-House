# Проверки перед коммитом

1. **Всегда** — тесты общего кода и типы всех пакетов (около 15 секунд):

   ```bash
   npm run check
   ```

2. **Если тронуты сервер, протокол или правила, которыми он пользуется** (`game-server/`, `shared/src/protocol.ts`, `shared/src/server/`, а также `fishing.ts`, `items.ts`, `rules.ts`, `world.ts`) — бот проходит игру через настоящий сервер (около 35 секунд):

   ```bash
   npm run smoke:own -w game-server
   ```

   Бот сам поднимает игровой сервер на свободном порту и гасит его; нужна только база (порт 5432, `npm run db:up`). Запущенный `npm run dev` не мешает и не задевается. Оба шага разом — `npm run check:all`.

3. **Если менялась схема базы** (`shared/src/server/schema.ts`) — до бота: `npm run db:generate`, затем `npm run db:migrate`. Применённые где-то ещё миграции руками не править.

4. **Если правка видна в игре** — после проверок посмотреть её в браузере: скилл `verify-game`.

## Что помнить

- Тесты и типы тронутых пакетов и так запускает хук в конце хода (`.claude/hooks/rules.mjs`); бота он не запускает — это шаг 2.
- Бот заводит в базе разработки игроков `бот_…` и `гость_…` — это нормально, убирать их не нужно.
- Новое сообщение или новое правило на сервере — повод дописать шаг в `game-server/scripts/smoke.ts` (и согласие сервера, и отказ), а не только прогнать старые.
- Отчёт — как есть: что запускалось, что упало и с каким выводом. Не запускалось — так и сказать.
