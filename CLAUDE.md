# Fishing House — заметки для работы над проектом

Уютная пиксельная онлайн-игра: общий причал, вход по имени и паролю, прогресс в базе. Цель по нагрузке — до 1000 игроков одновременно.

## Стек (решено, не менять без обсуждения)

| Часть | Что | Где |
|---|---|---|
| Фронт | Nuxt 4 + Vue 3 + TypeScript + Pinia; игра на canvas в `/play` | `app/` |
| API | Nuxt (Nitro): вход, регистрация, профили, билеты в игру; дальше — магазин | `app/server/` |
| Игровой сервер | Colyseus 0.18, несколько процессов + Redis | `game-server/` |
| База | PostgreSQL + Drizzle ORM | схема `shared/src/server/schema.ts`, миграции `shared/drizzle/` |
| Общий код | правила рыбалки, карта, рыбы, протокол, типы | `shared/` |
| Хостинг | VPS + Docker Compose + Caddy | `docker-compose.yml`, `Caddyfile`, `Dockerfile` |

## Как устроено

- **Монорепо на npm workspaces**: `shared`, `app`, `game-server`. `@fh/shared` подключается исходниками TypeScript (без сборки): в Nuxt через `build.transpile`, в игровом сервере — `tsx` в разработке и esbuild-бандл (`game-server/build.mjs`) в продакшене.
- **`@fh/shared`** работает и в браузере, и в Node. **`@fh/shared/server`** — только для серверов (база, билеты, `node:crypto`); в код `app/app/` его не импортировать, кроме `import type`.
- **Вход**: `nuxt-auth-utils`, сессия в зашифрованной cookie: `user = { id, name }`, где `id` — публичный id игрока (10 символов `[a-z0-9]`). Пароли — `hashPassword`/`verifyPassword` (scrypt).
- **В игру**: страница `/play` берёт у сайта билет (`POST /api/game/ticket`, HMAC общим `GAME_SECRET`, живёт минуту) и входит в комнату `pier` на Colyseus. `onAuth` комнаты проверяет билет и кладёт `id` игрока в `client.auth.id` — по нему `UniqueSessionPlugin` выбивает старую вкладку (причина `replaced`).
- **Кто главный**: сервер. Клиент ходит сам и шлёт место раз в 0,1 с; сервер проверяет проходимость и скорость (запас хода) и при несогласии шлёт `self`. Рыбалку целиком ведёт сервер (`createFishing` в `shared/src/fishing.ts`): клюёт, кто клюнул, успел ли подсечь (+`HOOK_GRACE` на задержку сети). Забросить можно только с удочкой в руке (`ITEMS.isRod`; её берут из рюкзака) и с ведром рядом; убрал удочку — рыбалка останавливается. Клиент лишь показывает фазы (`app/app/game/fishing-view.ts`).
- **Карта** 640×360 арт-пикселей — ровно 16:9, она же кадр игры: экран стоит на месте, камеры и масштаба нет; на экране 1920×1080 она рисуется ровно ×3 (ширины боков и полоса сверху в `sides` подобраны под это — менять их только вместе). В середине у нижнего края картинка-образец 240×320 (`World.pic` — где она стоит: x и y), и вокруг дома она остаётся как есть — её деревья, кусты, грибы, цветы и тропинки, точь-в-точь (меняется только вода под рекой). По бокам и сверху — трава с рекой и дорогой: их дорисовывает `tools/world-sides.mjs` по плану `sides` и `field` из `tools/world-shapes.mjs` (`field: null` вернёт прежний лес боков). На ней стоит лес из крон и кустов, вырезанных с картинки пиксель в пиксель (`tools/forest.mjs`, виды в `art/trees/forest/`), — список `trees` в `world-shapes.mjs`. На саму картинку деревья списка заходят только листвой и не дальше десятка пикселей — так закрыты швы; дерево, поставленное на своё место с картинки (`home`), лишь дорисовывает то, что срезала рамка. В чащу под кронами не зайти, у опушки герой прячется за деревьями. Прежняя карта — поле без леса — сохранена в `app/public/assets/draft/world.png` для следующего этапа. Разметка в `world-shapes.mjs` — в координатах картинки (левее неё x < 0, выше y < 0), всё в игре и в `world-data.ts` — в координатах карты; числа, снятые с картинки прямо в коде (как `bankY` в движке), сдвигать на `World.pic`. Сохранённые места игроков помнят `picX` и `picY` — положение картинки, при котором записаны; если картинку на карте сдвинуть, `cleanWorld` перенесёт их сам.
- **Дом** стоит на карте отдельным предметом, не запечённым в `world.png`: картинку `app/public/assets/house.png` (вырезана сборкой в `art/house/`) клиент рисует поверх карты (`app/app/game/house.ts`) там же, где дом на картинке-образце (`World.house`; место, контур, труба и свет — `shared/src/house.ts`). Его контур вычеркнут из проходимости в `shared/src/world.ts` (у клиента и сервера), за домом герой прячется по `World.depth`; ночью горят окна (`lights.png`, `glow.png`), из трубы идёт дым. Поэтому в сборке `house.onMap: false` и `house.sprite: true` в `tools/world-shapes.mjs` — так и оставить: сборка вырезает дом целиком в `art/house/` (сам дом, его свет, ореол и `house.json` — где что лежит), кладёт `house.png`, `lights.png` и `glow.png` в `app/public/assets/`, а в `world.png` закрашивает только сам дом — его тени на траве и всё вокруг остаются как на картинке. `World.smoke`, `World.lights`, `World.glow` берутся из `shared/src/house.ts`. `onMap: true` вместо этого запекает дом в карту вместе с двором вокруг него (`house.yard`).
- **Костёр** горит на лужайке справа от дома (`FIRE` в `shared/src/campfire.ts`, на карте — `World.fire`): очаг вычеркнут из проходимости, рисует его клиент (`app/app/game/campfire.ts`), ночью он светит, вблизи потрескивает; сидящий герой — кадр `HERO.seated` в `hero.ts`. У огня можно сесть (F или клик по костру): сообщение `rest`, сервер проверяет расстояние (`nearFire`) и ставит `rest` в состоянии комнаты; встают тем же `stand` или просто уходят. В базе это не хранится.
- **Что видят другие** — только состояние комнаты (`game-server/src/state.ts`: место, поза, ведро, рюкзак, есть ли в нём лампа, хвосты рыб). Лампа светит, только когда она в руке или стоит на земле (в рюкзаке — нет): из руки её ставят на землю и берут обратно, причём взять можно и чужую — тогда у вещи в базе меняется хозяин (G; `itemPut`, `itemPick` с pid хозяина; в базе — `items.ground`, тогда `x`, `y` вещи — место на карте; на сервере `Session.ground`, в состоянии комнаты `ground`, `gx`, `gy`). Ночью она освещает героя или место, где стоит: круг света клиент рисует в `drawNight` по полю `lamp` (сам ореол лампы и костра — `app/app/game/light.ts`). Зажечь и погасить её можно кнопкой или L, когда она в руке или стоит рядом (`ITEMS.lampNear`; сообщение `lamp`, помнится в `players.world.lamp`). Ведро и рыбалку игрок получает личными сообщениями (`ServerMessages` в `shared/src/protocol.ts`).
- **Время суток**: игровые сутки — `DAY_LENGTH` секунд (`shared/src/daytime.ts`), час считается от часов сервера (сообщение `clock` при входе), так что у всех он один. `skyAt(hour)` даёт цвет, на который клиент умножает кадр, и силу света в доме. Когда дом стоит на карте, свет на ней погашен, а горящие окна и фонарь — `lights.png`, ореол — `glow.png` (их собирает `build-world` по `house.lights` из `tools/world-shapes.mjs`). Пока только картинка: на рыбалку не влияет. В разработке часы причала переводятся из игры (нажать на часы): клиент шлёт `clock`, сервер сдвигает свои часы (`game-server/src/sky.ts`, сдвиг в памяти процесса) и рассылает новое время всем комнатам. В продакшене (`NODE_ENV=production`) сервер это сообщение не слушает; `DEV_TOOLS=1|0` задаёт это явно. `/play?hour=22` останавливает время только у себя.
- **Погода**: ясно, пасмурно, дождь или туман плюс ветер в любую из них (`shared/src/weather.ts`). Ведёт её сервер: расписание `weatherAt` считается от настоящего времени (одно на все процессы), `sky.ts` раз в секунду сверяется с ним и при перемене рассылает `weather` всем комнатам. Клиент только рисует (`app/app/game/weather-view.ts`): сила дождя, туч, тумана и ветра плавно догоняет то, что назвал сервер. В разработке погоду можно выставить из той же панели, что и часы (сообщение `weather`). Пока только картинка: на рыбалку не влияет.
- **Река** течёт только на экране (`app/app/game/river-view.ts`): воду и русло клиент снимает с самой карты, по руслу плывут штрихи течения. Маску воды оттуда же берёт погода — для кругов от капель.
- **Рюкзак**: лежит в мире, как ведро, либо надет (`WorldState.pack`); вид — один из `PACK_KINDS` (`shared/src/packs.ts`): расцветка рюкзака с картинки и вместимость — сетка клеток для вещей (`PACKS.grid`: от 4×3 у кожаного до 6×6 у ягодного, по порядку в `PACK_KINDS`). Надеть, снять и сменить вид можно свободно (на меньший — только если вещи в него влезут), но всё идёт через сервер (`packOn`, `packOff`, `packKind`).
- **Вещи в рюкзаке**: удочки, сети, топор, походная лампа и мелочь — `ITEMS` в `shared/src/items.ts`: имя, размер в клетках (1, 2 или 4; вещь можно повернуть), правила, куда она встаёт (`fits`, `spot`, `repack`, `settle`). Картинки — пиксельные карты в `app/app/game/items-art.ts` (клетка 24×24 арт-пикселя). Окно рюкзака — `components/GameBackpack.vue` (рисует `game/backpack-view.ts`): открывается на I или кнопкой, когда рюкзак на спине или рядом; вещи перетаскивают, R или правая кнопка поворачивают. Решает и пишет сервер (`itemMove`, `itemDrop`; не согласен — шлёт `items` целиком), записи вещей в базу идут по очереди. Вещи берут из рюкзака в руки. Рук две, а вещи двух весов (`heavy` в `ITEMS`): лёгкая занимает одну руку, тяжёлая — сеть-накидка и невод — обе; ведро в руке тоже занимает руку (`ITEMS.weight`, `load`, `canHold`). В базе это `items.held`, на сервере `Session.hands` (по порядку номеров), в состоянии комнаты `hand` и `off` — виды вещей. В окне рюкзака справа от сетки стоит рыбак с двумя гнёздами рук (тяжёлая вещь — одно широкое на оба): двойной клик, удержание или перетаскивание берут вещь в руки (`itemTake`; не хватает рук — прежние возвращаются в рюкзак) и убирают обратно (`itemStow`); правила — `ITEMS.take` и `ITEMS.stow`. В мире вещи видно в руках героя — первая в свободной руке, вторая в той, что носит ведро: маленькие картинки — `app/app/game/held-art.ts`, где кисти — `HERO.hand` и `HERO.hand2`. Пока вещь в руке, клеток она не занимает. Новому игроку при первом входе кладётся стартовый набор (`ITEMS.STARTER`, отметка `players.kit`). В разработке вещь можно положить из того же окна (`itemGive`, слушается вместе с часами и погодой).
- **Сохранение**: улов — сразу при подсечке (`catches`); вещи — сразу при перекладке и когда их берут в руку (`items`), вид рюкзака — сразу при смене; место героя, ведра и рюкзака (`players.world`, jsonb) — при выходе и раз в минуту. В старых записях рюкзака нет — `cleanWorld` кладёт его у дома.
- **Масштаб**: в комнате до `ROOM_SIZE` = 50 игроков, дальше матчмейкер открывает новую копию причала. Процессы игрового сервера связаны через Redis (`REDIS_URL`); каждый знает свой внешний адрес (`PUBLIC_ADDRESS`, например `domain/game/1`), Caddy ведёт `/game/N/*` на процесс N, а `/game/*` (матчмейкинг) — на любой.

## Команды

```bash
npm install                 # все пакеты сразу
cp .env.example .env        # и поменять секреты
npm run db:up               # Postgres и Redis для разработки (docker-compose.dev.yml)
npm run db:migrate          # применить миграции
npm run dev                 # сайт :3000 и игровой сервер :2567 вместе
npm test                    # тесты общего кода (node --test)
npm run typecheck           # типы во всех пакетах
npm run smoke -w game-server  # бот проходит игру через настоящий сервер (нужны база и запущенный game-server)
npm run db:generate         # после правки схемы — новая миграция в shared/drizzle
npm run build:world         # пересобрать карту и спрайты из art/reference.webp (нужен sharp)
docker compose up -d --build  # продакшен на VPS
```

## Правила

- Язык интерфейса, комментариев и коммитов — русский. Комментарии объясняют «зачем», в том же плотном стиле, что в коде.
- Новые сообщения клиент ⇄ сервер — сначала в `ClientMessages`/`ServerMessages` (`shared/src/protocol.ts`), на сервере — с zod-схемой в `onMessage`.
- Всё, что влияет на прогресс (улов, деньги, предметы), решает и записывает сервер. Клиенту не верить.
- Правила, нужные и клиенту, и серверу (скорости, расстояния, таблицы рыб), — только в `shared/`.
- Схему базы менять через `npm run db:generate` (миграции не править руками после того, как они применены где-то кроме своей машины).
- `shared/src/world-data.ts`, картинки в `app/public/assets/` и `art/house/` генерирует `tools/build-world.mjs` — руками не править. Исключение — `bucket.png`: в репозитории лежит правленая версия, после сборки её нужно вернуть (`git checkout app/public/assets/bucket.png`).
- Перед коммитом: `npm test`, `npm run typecheck`; если трогал сервер или протокол — `npm run smoke -w game-server`.
